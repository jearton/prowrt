# nlbwmon 三层终端统计适配

固件 [`25.12.6-20261124.3`](https://github.com/jearton/prowrt/releases/tag/v25.12.6-20261124.3) 已通过同镜像 VM 验收并发布；[发布证据](evidence/firmware-20261125/publication.json)。后台包为 `nlbwmon 2025.06.02~29236be6-r3`，界面包为 `luci-app-nlbwmon 26.288.56989~75a306d-r3`；中文翻译包保持原版。这是 ProWrt 的补丁版本，不是上游发行版。

## 来源与问题

- 后台：[jow-/nlbwmon](https://github.com/jow-/nlbwmon)，固定提交 `29236be687927b0c81ee6e2642e7caa8787c4ad3`。
- 界面：[OpenWrt LuCI 的 luci-app-nlbwmon](https://github.com/openwrt/luci/tree/75a306df84a020c57a631ef5b4c02ace56d93387/applications/luci-app-nlbwmon)。
- 三层终端保留 IP，但本机邻居表没有其 MAC。原版每条统计记录等待 500 ms 重试，积压达到 `database_limit` 后刷 MAC 查询队列错误。
- 该分支处理统计记录，不是业务包转发；日志不能直接证明业务丢包、内存耗尽或环路。
- 数据库本来就保存 IP，但原界面按 MAC 汇总，把零 MAC 的终端合并到同一项。

## 每项修改

- 删除每条记录等待 MAC 的延迟队列，查不到 MAC 时立即保留 IP 和流量计数。
- 查询成功仍使用真实 MAC，不拿下一跳交换机 MAC 代替终端，不生成伪 MAC。
- 查询失败缓存固定 4096 槽、5 秒有效期，使用单调时钟；碰撞淘汰旧项，约 128 KiB 内存，不随连接数增长。
- 到期允许重新识别 MAC；最初未知时的计数仍保留在 IP 记录，不按当前 DHCP 身份合并历史设备。
- 有观测流量的更新采用累加插入，保留先于 NEW 通知或 MAC 身份变化后的增量；只有 NEW 增加连接数，空更新不占用统计记录。
- LuCI 主机表按真实 MAC 汇总已识别设备，按 IP 区分未知 MAC，连接和协议明细链接跟随对应 IP。
- 无主机名时显示完整 IP，不把 IPv4 按域名截成第一段数字。
- 家族统计页也区分未知 IP，不把不同未知终端合并成同一个双栈主机。
- 数据库格式、已有历史、统计范围和数据库上限保持原样；不修改 DHCP、DNS、防火墙或接口归属。
- 构建入口校验上游配方、界面源码及补丁摘要，不兼容则中止。检查脚本实际运行 C 缓存代码和 LuCI 分组逻辑。

## 使用与限制

入口继续是 **服务 → 带宽监控**。后台与界面是两个 APK，均需更新；仅更新翻译包不能获得修复。数据库容量仍会限制统计记录，本次修复不消除容量限制。单凭统计记录不能确定物理端口或当前在线状态。

QuickStart 设备列表是另一套发现逻辑，兼容修复单独维护；Netdata 本轮不修改。通用固件不写入办公室特有网段。

## 验证与回滚

- 上游摘要、补丁应用、缓存重复查询／过期／恢复／固定容量检查通过。
- 实际生产记账函数的更新先于 NEW、空更新与连接计数检查通过。
- 189 上使用同版 OpenWrt x86_64 musl 工具链及 OpenWrt APK 打包流程构建；依赖沿用 `libubox20260213`、`libnl-tiny1` 等，不替换内核。
- 隔离 VM 在 `database_limit=32` 时复现原版队列错误；修复后保持该上限，不靠增大队列消除日志。
- r3 后台的 450 条 UDP 流完成载荷校验：两个无本机 MAC 的路由终端各 200 条、双向各 210400 字节；一个二层邻居 50 条、双向各 52600 字节，保留真实 MAC。
- 离线升级保留配置和此前计数；空闲刷新不重复累加；没有新增 MAC 队列溢出错误。
- Mac Chrome 实际显示两个独立路由 IP 和二层邻居；完整 IP 名称通过验证，见[截图](evidence/nlbwmon-20261124/mac-chrome.png)。
- 首个 r2 后台候选在一次精确计数检查中少一条方向的增量，未验收交付；原版与 r2 对照重复测试未重现该差值，不能宣称差值根因已完全证实。r3 补齐源码确认的更新丢失路径，并通过上述精确计数测试。

可审阅的后台验收数据见 [acceptance.json](evidence/nlbwmon-20261124/acceptance.json)。这属于包更新验收，完整镜像验收单独记录，不能将包更新测试与镜像测试混为一项。

更新前保留旧包及统计数据库备份；回滚安装原版 APK，配置和数据库格式兼容。VM 使用独立克隆盘，测试后已恢复原磁盘、接口和电源状态：9000 挂回 disk-21 并运行，第二网卡回到未挂桥状态，9001 保持关闭，移除本次两个流量命名空间。本流程不刷写生产设备。
